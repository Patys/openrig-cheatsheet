Work through one lead

Give the lead a concrete outcome, constraints and a way to check success. It coordinates specialists and review; you follow the task and result.

Rig & seat
A rig is a persistent team. A seat is a role with an address such as dev-build@starter. Its occupant or native conversation can change.
Context & skills
Context explains the project and where existing systems live. A router helps find it; a skill gives the procedure for a specific situation.
Spec & bundle
A RigSpec is the YAML blueprint. A bundle packages the team and its declared resources so another machine can install them.

Give the agent a map before details

Keep AGENTS.md as an entry point to the project’s architecture, decisions, current work and router skills. Show what already exists before asking for implementation. Read the relevant sources once the agent knows where to look.

Keep knowledge addressable and checkable

Link to one maintained source instead of copying it into every note. A library address such as world-public/start-here.md#what-to-trust selects a Markdown section; local project files use the addressable-Markdown resolver. Treat logs and expert recollections as evidence to check. Age alone does not make a note authoritative.

Recover context without changing the outcome

After compaction or a handover, re-read the current task, its source documents and acceptance criteria. Use the refocusing procedure when the session has drifted. Keep a short example of the mistake and its consequences in the appropriate project or seat notes so the next occupant can learn from it.

Scale a useful team

Start with one lead and one reviewed result. Add specialists or registered hosts when the work needs them. Another host needs its own runtime logins and explicit routing; the same rig name on two machines does not identify the same team. A bundle carries declared files, while host settings and retained session history have their own lifecycle.
